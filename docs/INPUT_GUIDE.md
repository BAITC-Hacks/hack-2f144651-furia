# Входные данные

Есть два способа: канонические таблицы или адаптеры отчётов IEK/Systeme по опубликованному аудиту. Оригинальные архивы не предоставлены; адаптеры пока испытаны только на синтетических макетах схем.

## Канонический импорт

ZIP содержит CSV UTF-8 по именам таблиц ниже; XLSX — листы с теми же именами. Один CSV называется, например, `policies.csv`. Поддержаны разделители `,` и `;`. Даты `YYYY-MM-DD`, числа без разделителей тысяч, идентификаторы текстовые. Пустота означает неизвестное; ноль — известный ноль.

| Таблица | Назначение / ключевые поля |
|---|---|
| products | supplier_id, sku_1c, supplier_sku, name, unit, category_id |
| sales | supplier_id, sku_1c, warehouse_scope, date, document_id, анонимный customer_id, quantity_signed, unit, document_type |
| monthly_sales | supplier_id, sku_1c, warehouse_scope, month (первое число), qty_net, is_complete, coverage_start, coverage_end |
| stock_snapshots | supplier_id, sku_1c, warehouse_scope, as_of, available **или** on_hand и reserved; snapshot_kind=current для текущего остатка |
| inbound | supplier_id, sku_1c, warehouse_scope, order_id, qty_base_unit, eta, eta_kind, status=confirmed/pending/cancelled |
| stockouts | supplier_id, sku_1c, warehouse_scope, start_date, end_date, evidence; границы включительно |
| policies | supplier_id, category_id (пусто = политика поставщика), lead_time_days, review_days, safety_days, min_order_qty, order_multiple, origin |
| growth_plan | supplier_id, sku_1c или category_id, start_date, end_date, extra_growth_rate, source |
| seasonal_prior | supplier_id, category_id, month_of_year, factor, known_as_of, source; 12 положительных коэффициентов |

Общие поля происхождения: source_file, source_sheet, source_row, data_mode=partner/synthetic/manual. Если они отсутствуют, импорт помечает источник и строку. Ручные изменения получают отметку manual; исходники на диске не меняются.

`sale` — продажа с исходным знаком; `return` — возврат (положительный ввод преобразуется в отрицательный). `receipt`, `customer_order` и неизвестные типы не являются продажами. Номер документа не становится идентификатором клиента. Для клиентской проверки используйте заранее обезличенные ID.

Категория выбирает явно заданную политику. Её код не интерпретируется как ABC автоматически. Дополнительный рост `0.10` = +10%, `-0.10` = −10%; это отдельный план относительно базовой модели. Пересекающиеся применимые планы блокируют прогноз. Приоритет: SKU → категория → поставщик.

У товара могут быть дополнительные поля `min_order_qty`, `order_multiple`, `quantity_rule_source`: они уточняют политику для SKU. `unconfirmed_moq` из IEK блокирует расчёт, пока смысл поля не подтверждён. После подтверждения перенесите значение в правильное поле и очистите `unconfirmed_moq`, либо повторите импорт с выбранной семантикой.

## Отчёты партнёра

1. «Мои данные» → «Отчёты IEK / Systeme», выберите поставщика и дату выгрузки.
2. Загрузите полный ZIP этого поставщика. Оригинальные файлы читаются в памяти; на диск не распаковываются.
3. Общую область склада подтверждайте только если все отчёты и склады динамики действительно относятся к этому пулу. Иначе агрегаты остаются UNSPECIFIED и не размножаются по складам.
4. Единицы пути подтверждайте только если все партии уже в базовых единицах товара. Иначе в inbound сохраняется `qty_source_unit`, статус pending и пустое `qty_base_unit`. Введите пересчитанное базовое количество и подтвердите партию вручную. Универсальной конверсии бухт/метров нет.
5. Задайте реальные/явно согласованные policies: сроки новых заказов, период пересмотра, страховой запас, MOQ/кратность. Категории IEK и неизвестные единицы задаются в products.
6. Для IEK внесите актуальный stock_snapshots с snapshot_kind=current и датой расчёта. Начальные месячные остатки не подходят.
7. При наличии добавьте stockouts и sales с обезличенным customer_id отдельным каноническим импортом. Не подменяйте отсутствие этих данных синтетикой.

Пустые Excel-ячейки не становятся нулями. Даты и заголовки проверяются; неизвестная версия выдаёт ошибку. Формулы читаются по сохранённым Excel-значениям; приложение не является Excel-вычислителем. AP/AQ/AR/AS Systeme не используются как достоверные готовые прогнозы. Год ETA 24.09 выводится из явно введённой даты отчёта и обозначается в eta_kind.

## Управление расчётом

Дата расчёта должна совпадать с подтверждённым текущим остатком. Редактор входных таблиц расположен над кнопкой расчёта. Нажимайте «Сохранить таблицу» после правки. Неизвестные параметры и ошибки видны отдельно от нулевого заказа. Дубли обязательных ключей и несопоставимые коды не удаляются молча.

Ручное количество и причина находятся в таблице «Проверка и экспорт». Правка количества не пересчитывает исходный прогноз; в экспорте есть `recommended_qty`, `final_qty`, `manager_override` и `reason`. Ручное решение может отступать от MOQ/кратности, поэтому требует причины. Фильтры просмотра не выбирают строки для экспорта — это отдельный флажок «В экспорт».

Защита: ZIP не извлекается на диск, запрещены абсолютные пути/`..`, лимит 100 файлов / 100 МБ распакованного содержимого. UI ограничивает один загружаемый файл 80 МБ. Текстовые формулы в итоговых CSV/XLSX обезвреживаются; числовые поля остаются числами. Для CSV в Excel задавайте тип кода «Текст».
