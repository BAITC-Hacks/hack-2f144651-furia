## Поведение и совместимость

classify_risk получает неизменённые строки Calculation.rows и config.as_of.
Единый mapping используется таблицей и карточкой: unavailable → «Нужны данные»,
calculated/unknown → «Риск не определён», critical → «Критично», risk или нужный
заказ → «Пополнение», none без заказа → «Норма». KPI/фильтр дефицита учитывают
только critical/risk; положительный страховой заказ сам по себе риска не означает.
Перепроверка включает warnings/unavailable/unknown. Цвет unknown добавлен в обе
карты цветов, чтобы новый статус не вызывал KeyError.

detector_status получает нормализованные продажи только одного KEY, config.as_of
и config.remove_oneoffs. Отключение и короткая история отображаются отдельно.
При evaluated наличие DemandResult подтверждает выполненную проверку; без него
показывается только применимость и недоступность результата. Незавершённый заказ
из-за отсутствия остатка не скрывает уже выполненный расчёт спроса.
Найденные события и реально применённые исключения считаются раздельно по applied;
пустой список не доказывает отсутствие аномалий. Предупреждения — в «Источниках».

Формулы Logic, контракты, CSV/XLSX и количества не менялись. Риск не зависит от
ручной правки; row_id, ноль, сброс утверждения и экспорт всего выбранного набора
сохраняются. UI не вычитает события и не восстанавливает спрос повторно.
