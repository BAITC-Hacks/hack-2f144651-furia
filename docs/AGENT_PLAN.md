# Единый план работы агентов EKT

Продолжаем существующее приложение. Направления разработки: **Frontend, Backend,
Logic**. **Интегратор** координирует работу и общие изменения; **Reviewer** выполняет
независимую проверку согласованного результата. Проверяющий подключается после
объединения, а не занимает ещё одну область продуктового кода.

Этот файл — единственная нормативная таблица владения файлами. Вложенные AGENTS
уточняют технические требования, но не расширяют разрешённую область.
[DEVELOPMENT](DEVELOPMENT.md) описывает архитектуру,
[INTERFACES](INTERFACES.md) — существующий API,
[TASKS](TASKS.md) — актуальные задачи и назначения,
[STATUS](STATUS.md) — результаты и ограничения. Источник истины для API — код.

## Владение файлами

Пути от корня репозитория. Область роли ограничивается конкретным поручением.
Для каталогов разрешены новые файлы своей зоны; перечисленные отдельные файлы
включают возможность создания отсутствующего файла. Исключения в столбце
«Граница» имеют приоритет над каталогом. Неперечисленный путь сначала назначает
интегратор. Запускать чужие тесты можно; менять их без назначения нельзя.

| Роль | Разрешённая область | Граница и отчёт |
|---|---|---|

| Backend | `src/ekt/application.py`, `src/ekt/ingest.py`, `src/ekt/partner.py`, `src/ekt/export.py`, `src/ekt/demo.py`, `tests/backend/`, `tests/test_partner.py`, `tests/test_partner_regressions.py`, `tests/test_ingest.py`, `tests/test_export.py`, `docs/INPUT_GUIDE.md`, `data/demo/README.md` | Все `AGENTS.md` принадлежат интегратору. Отчёт: `docs/handoffs/backend.md` |
| Logic | `src/ekt/demand.py`, `src/ekt/forecast.py`, `src/ekt/engine.py`, `src/ekt/review.py`, `tests/logic/`, `tests/test_demand.py`, `tests/test_forecast.py`, `tests/test_engine_regressions.py`, `tests/test_review.py`, `scripts/evaluate_forecast.py`, `docs/METHODOLOGY.md` | Все `AGENTS.md` принадлежат интегратору. Отчёт: `docs/handoffs/logic.md` |

Интегратор ведёт `docs/STATUS.md`, TASKS и шаблон handoff |

Существующие отчёты сохраняют авторство, SHA и фактические результаты. Новую запись
в handoff делает назначенный исполнитель, не переписывая прежнюю историю.
Исторические handoff не входят в общую область редактирования интегратора.
Отсутствие файла handoff означает, что отчёт ещё не создан, а не завершение роли.
Интегратор может делегировать ограниченную подзадачу своей зоны: сначала фиксирует
исполнителя и точные файлы в назначении, не передавая всю общую область.

## Границы, которые нельзя дублировать

- `src/ekt_ui/review.py` — экран Frontend; `src/ekt/review.py` — правила Logic.
  Logic определяет состав/статус экспортируемых строк, Backend сериализует их
  в CSV/XLSX через `src/ekt/export.py`.
- Backend ведёт демоданные. Изменение значений, от которых зависят общие числовые
  ожидания, согласует с интегратором и передаёт необходимые изменения приёмки.
- Публичные поля Bundle, Calculation, DemandResult, ForecastResult и Approval
  согласуются с интегратором и потребителями независимо от файла определения.
  Предложение содержит вход, текущий результат, нужный контракт и проверку.
- Общие `test_acceptance.py`, `test_edges.py`, `test_workflow.py`, `test_schema.py`
  и корневой `conftest.py` меняет интегратор. Исполнители добавляют новые проверки
  в своей зоне или передают ему конкретный сценарий. Делить один общий файл
  между одновременно работающими исполнителями нельзя.
- Один файл в один момент имеет одного исполнителя. При пересечении интегратор
  согласует передачу и завершение прежней работы до нового назначения.

## Назначение и выполнение

1. Интегратор проверяет свежий `origin/main` по [правилам Git](../AGENTS.md#git),
   сверяет TASKS и существующие сессии/назначения. Промпт не назначает роль.
2. Каждая задача получает ID, направление, конкретного исполнителя/сессию,
   полный базовый SHA, рабочую папку, точные разрешённые файлы, зависимости,
   критерии приёмки и владельца интеграции по [шаблону](TASK_TEMPLATE.md).
   Подзадачи одного параллельного этапа стартуют с общей согласованной базы.
3. Frontend, Backend и Logic работают параллельно только в независимых файлах.
   По вопросам общих контрактов сначала согласуется одно решение. Завершённые
   задачи из TASKS не запускаются заново из старого промпта или отчёта.
4. Исполнитель передаёт ранний проверяемый результат и затем handoff по
   [шаблону](handoffs/TEMPLATE.md): diff, проверки, ограничения и зависимые изменения.
   В общем дереве Git и установку общих зависимостей выполняет только интегратор.
5. Интегратор принимает части, проверяет область diff и совместимость. После
   завершённого проверенного изменения делает commit и push в `origin/main`;
   перед публикацией снова проверяет свежий main по корневым правилам Git.
6. Reviewer получает точный SHA и объём приёмки. Для документации проверяет
   ссылки, непротиворечивость и diff. Для продукта — затронутые сценарии, тесты
   и независимые числовые примеры; для полной приёмки — M1–M5 и пользовательский
   путь. Замечания возвращаются владельцам; после исправления проверка повторяется.

Для продуктовых изменений перед объединением выполняются релевантные тесты,
полный `python -m pytest -q` и `python scripts/smoke.py`. Чистая установка и
браузерная проверка выполняются, когда затронуты окружение/запуск и UI соответственно.
Для изменений только Markdown достаточно проверки ссылок, инструкций и
`git diff --check`; запуск продукта не выдаётся за выполненный.

## Совместимость со старыми названиями

Это только маршрут из исторических материалов, не дополнительные действующие роли:

| Старое имя | Действующее направление/функция |
|---|---|
| DATA | Backend; прежняя задача импорта становится конкретной Backend-задачей |
| ENGINE | Logic |
| LEAD | Интегратор; прежние UI-обязанности переданы Frontend, экспорт и демоданные — Backend, правила утверждения — Logic |

Старые промпты являются указателями на новые. Прежний план D/E/L сохранён в
[историческом снимке](history/AGENT_PLAN_LEGACY.md); статусы этих задач находятся
в TASKS. [Отчёт engine](handoffs/engine.md) сохранён как история Logic.
Старые упоминания владельцев в handoff/STATUS не отменяют эту таблицу.
Новые задачи и отчёты используют только действующие названия.
