# Проверка реально полученных файлов

Проверены оба ZIP, все 12 XLSX и их 14 листов. Заголовки и начальные строки прочитаны; в двух файлах динамики выполнен проход по всем строкам для дат, типов документов и знаков количества. Это аудит структуры, не завершённая очистка/сверка всей бухгалтерской модели. Полные профили и исходные файлы оставлены в локальном комплекте и не публикуются.

Источники: два архива, предоставленные командой. В публичной версии их нет; порядок локального добавления — в `source-materials/README.md`. Ниже сохранены схемы и инженерные выводы, без записей продаж и агрегированных объёмов операций. Строки и буквы Excel указаны с единицы.

## Особые ошибки, которых нужно избежать

1. **Знак количества.** В начале динамики встречаются отрицательные расходные накладные, но большинство количеств положительные. `abs()` завысит спрос. Сначала классифицировать тип документа; возвраты/корректировки учитывать отдельно, проверить месячную сверку. Заказ покупателя — не состоявшаяся продажа, приходная накладная — не спрос.
2. **ID клиента отсутствует.** Во всех заголовках динамики A:H нет клиента. B «Номер» — документ. Проверка выброса конкретного клиента возможна через дополнительный импорт `customer_id` и синтетический тест; на оригиналах доступен только уровень документа/даты/SKU.
3. **Stockout-интервалов нет.** Месячный ноль/пробел не равен всем дням отсутствия. Нужен дополнительный импорт периодов; оценку по месячным остаткам показывать только как сценарную и не включать по умолчанию в фактические дни stockout.
4. **Актуальный остаток IEK отсутствует.** Имеется начальный месячный остаток. Не выдавать сентябрьский за 22.09.2026 и не восстанавливать баланс только вычитанием продаж: неизвестны поступления. Предложить явный ввод актуального остатка или помеченный исторический сценарий.
5. **Несопоставимые склады.** Динамика содержит складской ключ, а остальные таблицы часто без него. Не присваивать им склад динамики автоматически. В real-data mode расчёт общего пула допустим только при явном допущении о совпадении области учёта; фильтр склада не должен размножать общий запас.
6. **Systeme V2 содержит сомнительные готовые формулы.** Проверено на r3: AP3 `=SUM(AC3:AO3)` — 13 месячных колонок, хотя подпись «последние 12 мес»; AQ3 `=AP3/12`. Пересчитать из выбранных завершённых месяцев, не использовать как безусловную истину.
7. **AR — изменение, не множитель.** AR3 `=SUM(AL3:AN3)/SUM(Z3:AB3)-1` с обработкой ошибки. AS тоже разность отношения и 1, а не индекс сезонности со средним 1. Не умножать спрос напрямую на отрицательный AR/AS. Внешний прогноз роста хранить отдельно от исторической оценки и не применять дважды.
8. **Резерв/подсклады.** AZ уже свободный остаток; не вычитать AY повторно. AX/AZ и AT:AW не суммировать без подтверждения областей. В BA3 формула использует несколько колонок, но сама по себе не доказывает, что их можно складывать для всех строк.
9. **Путь в правильных единицах.** В IEK встречается явное «закупаются бухтами, садятся метражом»; коэффициент упаковки нельзя вывести универсально из скобок в имени. Неясную конверсию вынести на проверку.
10. **Пробел и ноль.** В месячных таблицах много пустот. Сначала установить смысл пустых ячеек; политика заполнения для продаж и остатков различается. Не `fillna(0)` для всего импорта.
11. **2026 неполный.** Сентябрь идёт только до даты выгрузки. Октябрь–декабрь в сезонных файлах могут быть прогнозом; в IEK это прямо подписано. Нельзя использовать будущие значения как факт в backtest, сравнивать неполный сентябрь с полным или обучаться на данных после точки прогноза.
12. **Партнёрские сезонные агрегаты — не количества SKU.** Единицы не подтверждены, есть дробные суммы. Использовать их как явно указанный общий prior/сценарий коэффициентов, а не как штуки; SKU-сезонность проверять отдельно.

## Покрытие входов

| Вход | Что есть | Что сделать |
|---|---|---|
| История SKU | Месячные и документы обоих поставщиков | Импорт обоих видов, сверка на перекрытии; не двойной учёт |
| Текущий запас/резерв | Systeme V2; IEK только исторический | Явные дата/область; ввод актуальных данных IEK |
| Путь | Оба поставщика | Учитывать ETA; год 24.09 для Systeme вывести из даты отчёта с пометкой |
| Категория | Код категории Systeme V2 | Значение кодов не подтверждено; для IEK отдельный mapping |
| Рост | История и производный AR Systeme | Оценить устойчивый тренд; отдельный явный override прогноза прироста |
| MOQ/кратность | Оба архива, разные названия | Разделить minimum и multiple; проверить единицы/значение 0 |
| Lead time новых заказов | Отдельный справочник не найден | Явный ввод/демонстрационное допущение, не путать с ETA уже заказанного |
| Клиенты | Отсутствуют в динамике | Канонический анонимный импорт + синтетическая приёмка |
| Stockout | Отдельные периоды отсутствуют | Канонический импорт + синтетическая приёмка |
| Формат загрузки в 1С | Не предоставлен | CSV/XLSX со строковым кодом 1С; не обещать проверенную интеграцию |
| Материальная ведомость 1С | Отдельный файл с таким названием не найден; есть месячные отчёты и V2 | Уточнить, являются ли они требуемой ведомостью; не объявлять вход покрытым только по сходству названия |

Профиль отражает файлы, полученные 23.09.2026. Если партнёр выдаст обновление, проверить изменения схем и обновить аудит. Не переносить старые номера колонок без проверки заголовков.
