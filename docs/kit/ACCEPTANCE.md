# Приёмка — что будущий агент должен выполнить

Статус всех продуктовых тестов при создании комплекта: **не выполнены, приложения ещё нет**. Эти сценарии — предложенные проверки, а не официальные числовые пороги жюри. Тестировать чистые функции и пользовательский путь; не писать проверки, которые только ищут названия функций или заголовки.

## Импорт и края

- Сохранить `000001_` (синтетический пример) как строку; код, артикул и имя не подменяют друг друга.
- Обнаружить все 12 XLSX. Из дополнительных листов сезонности не создавать новые товарные строки. Итоги не участвуют в суммах как SKU/месяц.
- Подтвердить нормализацию положительных/отрицательных расходных накладных; покупки и заказы покупателя не считать продажами. Сверить несколько месяцев и SKU с агрегатом, показать расхождения.
- Пустой остаток != нулевой. Нет lead time/current stock/unit mapping → явный запрос входа/сценарный режим, не скрытая подстановка.
- Имеется `available=80, on_hand=100, reserved=20` → использовать 80, не 60 и не 180.
- Поздняя ETA не уменьшает закупку на текущий горизонт. Неизвестная ETA не считается своевременной без явно выбранного допущения.
- Одна партия inbound, случайно продублированная при импорте, обнаруживается; стабильное order_id не превращает две настоящие строки разных SKU в дубль.
- MOQ 10 и multiple 6 при потребности 11 → 12; ввод 0 как multiple считается невалидным, а не делением на ноль.
- У метров/упаковок отдельные units и конверсия; изменение области склада не присваивает общие остатки каждому складу.
- При cutoff до конца месяца будущие продажи не входят в обучение. Backtest не использует текущие stock/season factors как доступные в прошлом.

## Пользовательский путь

1. Новый пользователь запускает приложение по README без личной подписки.
2. Нажимает «Демонстрационные данные»: видит маркировку синтетики и получает воспроизводимый результат всех 5 требований.
3. Загружает реальные архивы: видит покрытие, отсутствующие поля, дату/область остатков и необходимые допущения. Получает результат по валидным входам без незаметной замены синтетикой.
4. Выбирает SKU: раскрывает расчёт, выбросы и stockout-оценку; числа сходятся.
5. Меняет путь/параметр роста: пересчитывается результат и обновляется объяснение.
6. Редактирует количество, в том числе 0, подтверждает; экспорт содержит выбранные значения и состояние. Изменение входов отменяет старое подтверждение.
7. Экспорт открывается, SKU не теряет нули; опасные текстовые формулы не исполняются. Никаких внешних сообщений не отправляется.
