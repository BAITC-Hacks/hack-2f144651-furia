# CI-02: причины красных статусов GitHub Actions

- Статус: done; временный ручной режим опубликован и проверен на GitHub.
- Цель: устранить повторяющиеся красные статусы новых коммитов с честным
  обозначением доступности автоматической проверки.
- Направление / функция: Интегратор; независимый Reviewer.
- Исполнитель / интегратор: Codex `/root`, текущая сессия CI-02.
- Reviewer: Codex `/root/ci_review`; передаёт результат интегратору.
- Рабочая папка: `/home/ziyadin/Documents/ChatGPT/Hack`, общее дерево, `main`.
- База после fetch/fast-forward: `398065eca0fcde77f791493b10ea88e41db7dae8`.
- Во время диагностики внешний интегратор обновил общее дерево до
  `f099198ea6c2d54ded05f020d8ae28be3316df31`, совпадающего с origin/main.
  Наши правки сохранены; workflow между этими SHA не менялся. Это согласованная
  база финальной проверки. С интегратором UI-LOGIC-01 согласованы раздельные файлы;
  TASKS/STATUS/review.md и Git передаются ему после завершения CI-02.
- Зависимость: INT-01; доступность GitHub Actions организации BAITC-Hacks.
- Разрешённые файлы интегратора: `.github/workflows/checks.yml`, `README.md`,
  `docs/TASKS.md`, `docs/STATUS.md`, `docs/tasks/CI-02.md`.
- Разрешённый файл Reviewer: `docs/handoffs/review.md`; остальное только чтение.
- Общие файлы назначены интегратору по AGENT_PLAN; пересечений с активными
  назначениями в TASKS нет. Git выполняет только интегратор.
- Контракт: Python API и продуктовые тесты без изменений; нельзя выдавать
  отключение автоматического запуска за успешное прохождение CI.
- Приёмка: подтверждена причина отказа, выбранный режим workflow проверен,
  документация соответствует режиму; после push проверено фактическое состояние
  нового SHA на GitHub. Прошлые результаты сохраняются.
- Решение пользователя: «Да, временно отключить автозапуск». Удалены только
  триггеры push/pull_request; workflow_dispatch, обе ОС и все шаги сохранены.
- Проверки и результат:
  - YAML разобран; единственный триггер `workflow_dispatch`; все настройки вне
    `on` поблочно совпадают с базой (jobs, шаги, ОС, права, concurrency).
  - Чистая копия `f099198ea6c2d54ded05f020d8ae28be3316df31` из `git archive`,
    Linux / Python 3.12.14, отдельная venv, установка `pip install -r requirements.lock`.
  - `python -m pytest -q`: **275 passed, 20 skipped**, 98.47 s.
    Пропущены opt-in проверки оригиналов без приватных архивов; это не их сверка.
  - `python -m pip check`: No broken requirements found.
  - `python scripts/smoke.py`: synthetic, 4 позиции, 2 поставщика,
    manual_zero=0, approval=approved, CSV/XLSX сформированы.
  - `python -m scripts.evaluate_forecast --demo --output work/evaluation.json`:
    успешная синтетическая оценка четырёх рядов.
  - Windows и удалённые jobs не запускались; код продукта в CI-02 не менялся.
- Ограничения: GitHub отклоняет jobs до первого шага из-за billing lock;
  текущий аккаунт имеет push, но не admin/maintain. Биллинг не меняется.
- Независимая проверка: [handoff Reviewer](../handoffs/review.md),
  блокирующих замечаний нет; Markdown-ссылки и `git diff --check` проверены.
- Итоговый коммит изменения: `9eb895c6076045cf9800e4d53192be4aa8504ac2`.
  Push в `origin/main` успешен; `git ls-remote origin refs/heads/main` подтвердил
  этот SHA. GitHub API: 0 workflow runs, 0 check runs и 0 commit statuses
  для него. Опубликованный YAML содержит только `workflow_dispatch`.
  Эта запись фиксирует фактическую удалённую проверку отдельным коммитом документации.

## Подтверждённая причина

[Запуск 35853319926](https://github.com/BAITC-Hacks/hack-2f144651-furia/actions/runs/35853319926)
для базового SHA: обе jobs завершились failure без единого шага.
Annotations обеих jobs: “The job was not started because your account is locked
due to a billing issue.” Это отказ инфраструктуры до выполнения тестов.
