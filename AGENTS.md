# EKT — инструкции для всех агентов

Это официальный репозиторий Furia: `https://github.com/BAITC-Hacks/hack-2f144651-furia.git`.
Приложение уже существует. Продолжайте MVP, не создавайте проект заново.
Отвечайте по-русски. Сначала прочитайте [START_HERE.md](START_HERE.md),
[состояние](docs/STATUS.md), [план ролей](docs/AGENT_PLAN.md),
[архитектуру Frontend/Backend/Logic](docs/DEVELOPMENT.md) и свой промпт.

## Режим Работы

- Основные роли DATA, ENGINE, LEAD и REVIEWER назначаются по `docs/AGENT_PLAN.md`; вложенные AGENTS уточняют ответственность Frontend, Backend и Logic по коду и тестам.
- Для работы Codex по прямому поручению пользователя базовая ветка — `main`: не создавать отдельную feature-ветку, если пользователь явно не попросил. Проверить `git status`, обновить `main` без перезаписи истории, внести только порученные изменения и сообщить результат. Это не общее разрешение на будущие commit/push.
- В командном потоке интеграционные коммиты выполняет LEAD; DATA/ENGINE придерживаются назначенных областей из AGENT_PLAN. Явное поручение пользователя Codex работать в main имеет приоритет для текущей задачи.
- Push, публикация и деплой выполняются по явному поручению пользователя для соответствующего этапа. Историческое разрешение в STATUS не является постоянным.
- Сохраняйте файлы, действующие remotes, Git-историю и чужие изменения. Не выполняйте `git init`, смену origin, force push, reset --hard или перезапись дерева. Не копируйте `.git` из комплекта подготовки.
- Перед работой: `git status --short --branch`, `git rev-parse HEAD`, чтение инструкций. При чужих изменениях в назначенных файлах согласуйте владение; независимую работу продолжайте.
- При работе командных ролей не занимайте выданную DATA/ENGINE роль и не запускайте все промпты.

## Владельцы И Контракт

| Зона | Основные файлы | Инструкция |
|---|---|---|
| Frontend | `src/ekt_ui/`, `.streamlit/config.toml`, `tests/frontend/` | `src/ekt_ui/AGENTS.md` |
| Backend | `src/ekt/application.py`, `ingest.py`, `partner.py`, `export.py`, `demo.py`, backend tests | `src/ekt/AGENTS.md` |
| Logic / ENGINE | `src/ekt/demand.py`, `forecast.py`, `engine.py`, `review.py`, acceptance tests | `src/ekt/AGENTS.md`, `docs/AGENT_PLAN.md` |
| Общий контракт / LEAD | `schema.py`, публичные поля Calculation, `app.py`, общие fixtures и интеграция | `docs/INTERFACES.md`, `docs/AGENT_PLAN.md` |

Frontend вызывает функции пакета ekt в том же Python-процессе; отдельного JS-клиента и HTTP API нет. Backend и Logic не импортируют Streamlit или ekt_ui; формулы не копируются в UI. DATA владеет адаптерами и импортом, ENGINE — вычислением; точные ограничения файлов остаются в AGENT_PLAN.

Реальный контракт — `src/ekt/schema.py` и [INTERFACES.md](docs/INTERFACES.md). `docs/kit/DATA_CONTRACTS.md` — исходная спецификация, а не точные имена API. Не создавайте второй Bundle, contracts.py, normalize.py или replenish.py. Изменение общего интерфейса согласуйте с LEAD. Зависимости, общие fixtures и конфигурацию меняет LEAD. Каждый исполнитель обновляет только свой handoff; общий STATUS обновляет LEAD.

## Ветки И Коммиты

Для порученных Codex изменений работайте прямо в `main`. Не создавайте ветки автоматически. Если пользователь прямо запросил отдельную ветку, соблюдайте это указание.

В назначенной параллельной работе команды следуйте AGENT_PLAN и сохраняйте владение файлами. Согласуйте общий контракт до реализации; один интегратор отвечает за сквозную совместимость. Не создавайте ветку вопреки явному запросу пользователя работать в main. Историю не переписывать, чужие изменения при конфликте не стирать.

## Инварианты И Готовность

- Числа рассчитываются локально; API-ключ для основного сценария не нужен. Нет отправки заказов или исходных данных внешним сервисам.
- Синтетика, данные партнёра и ручные допущения различаются. Неизвестное не подменяется нулём или выдуманным фактом.
- Сохраняйте строковые коды, единицы, scope, происхождение и знаки продаж. Не суммируйте историю с её детализацией, снимки остатков по времени и резерв повторно.
- Документ не является клиентом; месячный нулевой остаток не доказывает дни stockout. IEK month_start не является текущим остатком.
- Все M1–M5 обязательны. Тесты макетов не означают проверенный реальный импорт.
- Сырые архивы, клиентские записи, секреты и диагностические выгрузки не коммитить; `git add -f` не использовать.
- Учитывайте дедлайн и актуальные указания организаторов. Не выдавайте поздние изменения за сданные вовремя.
- Сообщайте только выполненные проверки, реальные ограничения и статус публикации. Локальная готовность не равна официальной сдаче.
