# EKT — инструкции для всех агентов

Это официальный репозиторий Furia: `https://github.com/BAITC-Hacks/hack-2f144651-furia.git`.
Приложение уже существует. Продолжайте MVP, не создавайте проект заново.
Отвечайте по-русски. Сначала прочитайте [START_HERE.md](START_HERE.md),
[состояние](docs/STATUS.md), [план ролей](docs/AGENT_PLAN.md) и свой промпт.

## Режим работы

- Пользователь поручил разделить дальнейшую работу между агентами. Прежняя инструкция об одном исполнителе заменена планом ролей.
- Разрешены локальные изменения, изолированные зависимости, запуск и проверки. В общем working tree коммиты делает только LEAD; в отдельной ветке исполнитель коммитит только назначенные файлы.
- Push, публикация и деплой требуют явного указания пользователя для текущего этапа. Историческое разрешение другому агенту в STATUS не является постоянным разрешением.
- Сохраняйте файлы, действующие remotes, Git-историю и чужие изменения. Не выполняйте `git init`, смену origin, force push, reset --hard или перезапись дерева. Не копируйте `.git` из комплекта подготовки.
- Перед работой: `git status --short --branch`, `git rev-parse HEAD`, чтение инструкций. При чужих изменениях в назначенных файлах сначала согласуйте владение; независимую работу продолжайте.
- Без назначенной роли выполните чтение и запросите роль у ведущего. Не запускайте все промпты и не занимайте уже занятую роль.

## Владельцы и контракт

- DATA владеет импортом, ENGINE — расчётом, LEAD — общей схемой/UI/экспортом/интеграцией. Точные разрешённые пути указаны в AGENT_PLAN.
- Реальный контракт — `src/ekt/schema.py` и [INTERFACES.md](docs/INTERFACES.md). `docs/kit/DATA_CONTRACTS.md` содержит исходное предложение, а не точные имена API.
- Не создавайте второй Bundle, `contracts.py`, `normalize.py` или `replenish.py` параллельно существующим модулям. Изменение общего интерфейса согласуйте с LEAD.
- Зависимости, общие fixtures, конфигурация и STATUS меняются только ведущим. Не устанавливайте оркестраторы; сохраняйте Python/Streamlit стек.
- Каждый исполнитель обновляет только свой handoff; проверяющий продуктовый код не редактирует.

## Инварианты и готовность

- Числа рассчитываются локально; API-ключ для основного сценария не нужен. Нет отправки заказов или исходных данных внешним сервисам.
- Синтетика, данные партнёра и ручные допущения различаются. Неизвестное не подменяется нулём или выдуманным фактом.
- Сохраняйте строковые коды, единицы, scope, происхождение и знаки продаж. Не суммируйте историю с её детализацией, снимки остатков по времени и резерв повторно.
- Документ не является клиентом; месячный нулевой остаток не доказывает дни stockout. IEK month_start не является текущим остатком.
- Все M1–M5 обязательны. Используйте независимые числовые примеры; тесты макетов не означают проверенный реальный импорт.
- Сырые архивы, клиентские записи, секреты и диагностические выгрузки не коммитить; `git add -f` не использовать.
- Учитывайте фактическое время: в комплекте указан дедлайн 23.09.2026 18:00 Asia/Almaty; уточнения организаторов имеют приоритет. Поздние изменения не выдавайте за сданные вовремя.
- Сообщайте только выполненные проверки, реальные ограничения и статус публикации. Официальную сдачу не приравнивайте к локальной готовности.
