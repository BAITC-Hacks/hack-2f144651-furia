# Backend И Logic

Назначение ролей и единственная таблица разрешённых путей —
[AGENT_PLAN.md](../../docs/AGENT_PLAN.md). Этот файл уточняет технические правила
пакета; общие правила работы с Git — в [корневом AGENTS.md](../../AGENTS.md).

Здесь нет UI, session_state, Streamlit, сетевых вызовов и глобального состояния сессии.
Пакет используется интерфейсом, CLI smoke и тестами напрямую.

## Backend

- application.py: импорт набора, замена поставщика, сохранение ручной таблицы и provenance.
- ingest.py: канонические ZIP/CSV/XLSX, ограничения архивов и объединение таблиц.
- partner.py: адаптеры IEK/Systeme, заголовки, даты, единицы, исходные допущения.
- export.py: безопасные CSV/XLSX, текстовые SKU, метаданные расчёта.
- demo.py: воспроизводимые синтетические данные и ZIP входов.
- Изменение демоданных, затрагивающее общие числовые ожидания приёмки,
  согласовать с Интегратором до правок.
- Функции изменения набора возвращают новую копию, не меняют входы или кеш клиента.
- Сериализация получает готовую таблицу; не переносить в export.py правила
  ручного решения и утверждения из review.py.
- Проверки зоны: tests/backend/, tests/test_partner.py, tests/test_partner_regressions.py.

## Logic

- demand.py: продажи/возвраты, разовые события, месячная сверка, stockout.
- forecast.py: сезонность, тренд, cutoff и дополнительный рост.
- engine.py: политика, горизонт, остаток/путь, MOQ/кратность, риск и объяснения.
- review.py: правки менеджера, причина, подпись утверждения и статус экспорта.
- review.py не управляет виджетами: пользовательское представление находится
  в src/ekt_ui/review.py. export_frame формирует результат решения менеджера,
  а запись CSV/XLSX выполняется отдельно в export.py.
- Не читать файлы и не форматировать виджеты внутри расчётных функций.
- Изменение формулы требует причинного теста с известным результатом и
  согласованного обновления docs/METHODOLOGY.md по правилам владения документацией.
- Проверки зоны: tests/test_demand.py, tests/test_forecast.py,
  tests/test_engine_regressions.py, tests/test_review.py; новые — в tests/logic/.

Все роли могут запускать общую приёмку и scripts/smoke.py. Право менять общие
тесты и фикстуры определяется AGENT_PLAN; не делить один общий тестовый файл
между одновременно работающими исполнителями.

## Общий Контракт

schema.py (Bundle, SCHEMAS, normalize, validate, fingerprint), публичные поля
Calculation, DemandResult, ForecastResult и Approval согласуются с Интегратором
и потребителями перед изменением контракта независимо от расположения класса.
При разделении одной фичи Backend отвечает за ввод/вывод, Logic за числовое правило,
Frontend за отображение. Интегратор проверяет совместимость и полный пользовательский путь.
