# EKT · объяснимые заказы поставщикам

Работающий MVP: локальный прогноз регулярного спроса и расчёт закупок, Streamlit-интерфейс, просмотр компонентов, корректировка, утверждение и экспорт CSV/XLSX. Демо **полностью синтетическое**. Реальных архивов партнёра пока нет.

## Передача и командная разработка

Начните с [START_HERE.md](START_HERE.md). Назначения DATA/ENGINE/LEAD/REVIEWER
описаны в [AGENT_PLAN.md](docs/AGENT_PLAN.md), реальные Python-интерфейсы — в
[INTERFACES.md](docs/INTERFACES.md). Передавайте каждому исполнителю одну роль,
базовый SHA и соответствующий промпт; ограничения файлов остаются в плане.

Интерфейс приложения находится в `src/ekt_ui/`, операции над наборами данных —
в `src/ekt/application.py`, адаптеры и расчётная логика — в `src/ekt/`. Это слои
одного Python-приложения, отдельного HTTP API нет; запуск через корневой `app.py`
сохранён.

[Карта файлов, архитектура и история коммитов](docs/DEVELOPMENT.md),
[задачи Frontend / Backend / Logic](docs/TASKS.md),
[шаблон задачи](docs/TASK_TEMPLATE.md). Для порученной Codex работы изменения
вносятся прямо в `main`; отдельная ветка создаётся только по прямому запросу.


## Запуск (Windows / Python 3.12)

```powershell
.\setup.ps1
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Запускайте команды из корня этой копии репозитория. `setup.ps1` создаёт только локальную `.venv`: использует Python 3.12 из `py` либо комплектного окружения Codex, если оно установлено. Для другого расположения: `.\setup.ps1 -PythonExe 'C:\path\to\python.exe'`. Скрипт не меняет системные настройки или политику выполнения PowerShell.

Если скрипты PowerShell запрещены, выполните обычные команды в терминале с установленным Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m streamlit run app.py
```

## Запуск (Linux / macOS, Python 3.12)


```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m streamlit run app.py
```

Если Python предоставлен без pip/venv, доступен вариант через установленный uv:

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.lock
.venv/bin/python -m streamlit run app.py
```

Интернет требуется для первоначальной установки пакетов; расчёт работает локально без сети.

Откройте http://127.0.0.1:8501, нажмите «Загрузить демо» → «Рассчитать предложения». Просмотрите объяснение, измените количество с причиной, утвердите и скачайте файл. Ноль поддерживается как ручное решение. Изменение входов или корректировки отменяет прежнее утверждение.

Расчёты не требуют API-ключей. Сервер слушает только 127.0.0.1; телеметрия Streamlit отключена. Заказы не отправляются поставщикам.

## Возможности

| Требование | Реализация |
|---|---|
| M1 · Базовый заказ | Продажи, дата/область текущего запаса, подтверждённый путь с ETA, политика категории, отдельный план роста |
| M2 · Сезонность и рост | Календарные коэффициенты SKU при ≥2 циклах, иначе prior; устойчивый тренд десезонализированного дневного уровня |
| M3 · Дефицит | Восстановление только по явно подтверждённым интервалам, объединение пересечений |
| M4 · Разовые заказы | Устойчивый порог размера события, группировка клиента за день, проверка повторяемости и массового пика |
| M5 · Предложение | Поставщик, SKU, единицы, приоритет, риск по датам, компоненты и объяснение каждой строки |
| Работа менеджера | Фильтры поставщика/области/категории, входные таблицы, корректировка с причиной, локальное утверждение, CSV/XLSX |

## Входы и ограничения

Канонический импорт: ZIP с CSV по именам таблиц из [контракта](docs/kit/DATA_CONTRACTS.md), XLSX с такими же именами листов, либо отдельные CSV. Шаблон с синтетическими данными скачивается в приложении. Идентификаторы сохраняются строками.

Пошаговое описание таблиц и недостающих полей: [docs/INPUT_GUIDE.md](docs/INPUT_GUIDE.md). Для дополнения текущего набора включите «Дополнить текущий набор»: загруженная таблица заменяет одноимённую **целиком**. Для отчётов партнёра загружайте полный ZIP одного поставщика; повторный импорт заменяет данные именно этого поставщика.

Дополнительно реализованы адаптеры IEK/Systeme по аудиту; проверены только на синтетических макетах. Отсутствующие customer_id, интервалы stockout, сроки, текущий остаток и единицы не выдумываются. Нужные параметры можно ввести в редакторе таблиц. IEK «начальный остаток» не считается текущим; AP/AQ/AR/AS Systeme не используются как готовый прогноз. Неизвестная область склада и конверсия пути блокируют точный заказ.

Метод: исключение редких крупных документных/клиентских событий, объединение подтверждённых stockout-интервалов и восстановление спроса, календарная сезонность SKU или prior, устойчивый тренд, отдельный план роста. Заказ: прогноз + страховой запас − доступный остаток − своевременный подтверждённый путь, затем MOQ и кратность. Методология MVP не является доказательством точности или экономии на реальных данных.

Подробнее: [методология](docs/METHODOLOGY.md), [ограничения](docs/DATA_LIMITATIONS.md), [демонстрация](docs/DEMO.md), [сторонние компоненты](THIRD_PARTY.md). Основной код — `src/ekt/`; расчётные функции не зависят от Streamlit. `data/demo` не содержит партнёрских записей: демо воспроизводимо генерируется в `src/ekt/demo.py`.

Утверждение хранится в сессии приложения; экспорт сохраняет статус и параметры. Перезапуск сессии сбрасывает несохранённую работу. XLSX сохраняет текстовые коды; при открытии CSV в Excel импортируйте столбец кода как текст. Экспорт для согласования; совместимость с конкретным импортом 1С не проверена.

Подготовительный комплект: https://github.com/Ziyadin23/hackalem-ekt-agent-kit, commit `527b3004c01da60b0e63b10e0d2aaa3304dcd0ba`. Реализация создана локально с настоящими датами коммитов; пользовательское разрешение на разработку не выдаётся за разрешение организаторов.
