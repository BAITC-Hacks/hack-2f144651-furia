# EKT · объяснимые заказы поставщикам

Промежуточный работающий MVP: локальный расчёт, Streamlit-интерфейс, просмотр компонентов, корректировка, утверждение и экспорт CSV/XLSX. Демо **полностью синтетическое**. Реальных архивов партнёра пока нет.

## Передача другим агентам

Начните с [START_HERE.md](START_HERE.md). Назначения и разрешённые файлы описаны
в [AGENT_PLAN.md](docs/AGENT_PLAN.md), реальные API — в
[INTERFACES.md](docs/INTERFACES.md). DATA и ENGINE дорабатывают существующие
модули параллельно; LEAD интегрирует, REVIEWER проверяет общий результат.
Каждому исполнителю передайте одну роль, одинаковый полный SHA и соответствующий
промпт. Не выдавайте одну область двум агентам одновременно.

## Запуск (Windows / Python 3.12)

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock
.venv\Scripts\python.exe -m streamlit run app.py
```

## Запуск (Linux / macOS, Python 3.12)

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m streamlit run app.py
```

Если Python предоставлен без pip/venv, доступен вариант через установленный uv:

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.lock
.venv/bin/python -m streamlit run app.py
```

Откройте http://127.0.0.1:8501, нажмите «Загрузить демо» → «Рассчитать предложения». Просмотрите объяснение, измените количество с причиной, утвердите и скачайте файл. Ноль поддерживается как ручное решение. Изменение входов или корректировки отменяет прежнее утверждение.

Расчёты не требуют API-ключей. Сервер слушает только 127.0.0.1; телеметрия Streamlit отключена. Заказы не отправляются поставщикам.

## Проверки

```powershell
.venv\Scripts\python.exe -m pytest -q
```

На Linux/macOS команда проверки: `.venv/bin/python -m pytest -q`.
Это промежуточная версия. Фактические результаты, ограничения и следующий шаг:
[docs/STATUS.md](docs/STATUS.md). Зелёные тесты на синтетике не подтверждают
проверку оригинальных архивов или точность прогноза на данных партнёра.

## Входы и ограничения

Канонический импорт: ZIP с CSV по именам таблиц из [контракта](docs/kit/DATA_CONTRACTS.md), XLSX с такими же именами листов, либо отдельные CSV. Шаблон с синтетическими данными скачивается в приложении. Идентификаторы сохраняются строками.

Дополнительно реализованы адаптеры IEK/Systeme по аудиту; проверены только на синтетических макетах. Отсутствующие customer_id, интервалы stockout, сроки, текущий остаток и единицы не выдумываются. Нужные параметры можно ввести в редакторе таблиц. IEK «начальный остаток» не считается текущим; AP/AQ/AR/AS Systeme не используются как готовый прогноз. Неизвестная область склада и конверсия пути блокируют точный заказ.

Метод: исключение редких крупных документных/клиентских событий, объединение подтверждённых stockout-интервалов и восстановление спроса, календарная сезонность SKU или prior, устойчивый тренд, отдельный план роста. Заказ: прогноз + страховой запас − доступный остаток − своевременный подтверждённый путь, затем MOQ и кратность. Методология MVP не является доказательством точности или экономии на реальных данных.

Утверждение хранится в сессии приложения; экспорт сохраняет статус и параметры. Перезапуск сессии сбрасывает несохранённую работу. XLSX сохраняет текстовые коды; при открытии CSV в Excel импортируйте столбец кода как текст. Экспорт для согласования; совместимость с конкретным импортом 1С не проверена.
