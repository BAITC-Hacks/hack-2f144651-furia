# Проверки По Зонам

Единственная таблица владельцев тестовых файлов и разрешённых путей —
[AGENT_PLAN.md](../docs/AGENT_PLAN.md). Описание ниже объясняет назначение проверок,
не назначает исполнителей. Общие правила работы с Git — в
[корневом AGENTS.md](../AGENTS.md).

- frontend/: Streamlit AppTest через корневой app.py, события и состояние сессии.
- backend/: операции application, копирование входов, provenance и изоляция поставщиков.
- logic/: новые независимые числовые проверки и правила решения менеджера.
- test_partner.py, test_partner_regressions.py: синтетические схемы IEK/Systeme и регрессии импорта.
- test_demand.py, test_forecast.py, test_engine_regressions.py: спрос, прогноз и расчёт заказа.
- test_review.py: идентичность строк, правки менеджера и утверждение.
- test_acceptance.py: обязательные причинные сценарии M1-M5/T1-T12.
- test_edges.py: общие краевые случаи импорта, расчёта и экспорта.
- test_workflow.py: сквозной импорт/расчёт/утверждение/экспорт без UI.
- test_schema.py: общий контракт и валидация данных.
- conftest.py: общий контракт синтетических фикстур; сохранять совместимость.

Все роли могут запускать любой набор тестов. Изменения общей приёмки, смешанных
тестовых файлов и общих фикстур передавать Интегратору согласно AGENT_PLAN;
наличие теста своей функции не даёт права редактировать общий файл. Reviewer
проводит проверку и записывает результаты в свой handoff, продуктовые тесты не меняет.

Тестировать поведение, а не наличие заголовков или имён файлов. Новые независимые
проверки помещать в отдельный файл своей назначенной зоны, чтобы уменьшить конфликты.
Для продуктовых изменений полная проверка перед объединением:
python -m pytest -q и python scripts/smoke.py. Для изменений только Markdown
достаточно проверки документации по AGENT_PLAN.
