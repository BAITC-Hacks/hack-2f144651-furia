# Начало работы агента EKT

Здесь уже есть приложение EKT. Продолжайте существующий код. Рабочие направления —
Frontend, Backend и Logic; общий результат координирует Интегратор, независимую
проверку выполняет Reviewer. Наличие промпта не означает назначение исполнителя.

## Где находится актуальная информация

- [AGENTS.md](AGENTS.md) — общие правила и постоянное поручение commit/push.
- [AGENT_PLAN.md](docs/AGENT_PLAN.md) — единственная нормативная таблица владения файлами.
- [TASKS.md](docs/TASKS.md) — актуальный backlog, назначения и зависимости.
- [STATUS.md](docs/STATUS.md) — результаты, ограничения и история проверок.
- [DEVELOPMENT.md](docs/DEVELOPMENT.md) — описание архитектуры Frontend/Backend/Logic.
- [INTERFACES.md](docs/INTERFACES.md) и `src/ekt/schema.py` — действующий контракт.

Прочитайте эти документы, вложенные `AGENTS.md` своей области и один назначенный
промпт. Старые задачи и отчёты остаются историей: не повторяйте завершённые работы
из прошлых поручений без нового назначения в TASKS.

## Выберите назначенную роль

| Роль | Промпт | Результат |
|---|---|---|
| Frontend | [FRONTEND_AGENT.md](prompts/FRONTEND_AGENT.md) | Интерфейс и поведение пользовательской сессии |
| Backend | [BACKEND_AGENT.md](prompts/BACKEND_AGENT.md) | Ввод, обработка данных и форматы файлов |
| Logic | [LOGIC_AGENT.md](prompts/LOGIC_AGENT.md) | Спрос, прогноз, заказ и правила утверждения |
| Интегратор | [INTEGRATOR_START.md](prompts/INTEGRATOR_START.md) | Назначения, общий контракт, интеграция и публикация кода |
| Reviewer | [REVIEWER.md](prompts/REVIEWER.md) | Независимая проверка согласованной версии |

Одна задача получает конкретного исполнителя, точные файлы и одного интегратора.
Frontend, Backend и Logic могут работать параллельно при непересекающихся файлах.
Если назначение отсутствует, выполните чтение и запросите его у интегратора.
Старые ссылки DATA, ENGINE и LEAD ведут на новые промпты; отдельными действующими
ролями эти названия больше не являются.

## Перед изменениями

```bash
git status --short --branch
git rev-parse HEAD
git remote -v
```

Перед новой задачей интегратор проверяет дерево, выполняет `git fetch origin`
и обновляет чистый `main` до `origin/main` через fast-forward. Если есть чужие
правки, сначала сохраняет их и согласует затронутое владение. Историю и чужие
файлы не перезаписывает. База не закрепляется за историческим SHA: каждому
исполнителю передаётся полный SHA после этого обновления.

В общем рабочем дереве этот цикл проводится один раз до запуска параллельных
подзадач. Только интегратор выполняет Git-операции, меняющие состояние репозитория;
исполнители сверяют SHA и статус, но не делают fetch, checkout, merge, add, commit
или push. Пока исполнители работают, ветку и общую базу не менять. Установку
зависимостей также координирует интегратор.

Работа Codex по умолчанию идёт прямо в `main`. Отдельная ветка создаётся только
по явному запросу пользователя. После каждого завершённого и проверенного блока
интегратор коммитит относящиеся к нему файлы и делает push в `origin/main` без
повторного разрешения; новое явное указание «без commit/push» имеет приоритет.
Перед публикацией интегратор снова проверяет актуальность удалённого main и
устраняет расхождения без force push и переписывания истории. Разрешение на push
не разрешает деплой, официальную сдачу или отправку заказов.

Установка и запуск — в [README](README.md). Проверки выбирайте по объёму задачи:
для документации — ссылки, согласованность и diff; для кода — затронутые тесты
и согласованная приёмка. Не называйте прошлые результаты проверкой новой версии.

## Сообщение для назначения

Скопируйте блок, оставьте одну роль и заполните поля. Назначение фиксируется
в TASKS по [шаблону задачи](docs/TASK_TEMPLATE.md).

```text
Репозиторий: https://github.com/BAITC-Hacks/hack-2f144651-furia
Задача: <ID и конкретная цель из docs/TASKS.md>.
Роль: Frontend / Backend / Logic / Интегратор / Reviewer.
Исполнитель: <имя агента или однозначный идентификатор сессии>.
База: <полный SHA актуального main после fetch/fast-forward интегратора>.
Рабочая папка: <абсолютный путь>.
Режим: <общее дерево main либо отдельный режим по явному запросу пользователя>.
Разрешённые файлы: <точный список в пределах docs/AGENT_PLAN.md>.
Зависимости: <ID задач, согласованные API, необходимые входы>.
Приёмка: <наблюдаемое поведение и необходимые проверки>.
Интегратор: <имя агента или однозначный идентификатор сессии>.
Архивы партнёра: <локальные пути либо «не переданы»>.
Прочитай START_HERE.md и назначенный промпт. Продолжай существующий код.
В общем дереве Git выполняет интегратор. Передай результат и список файлов
по docs/handoffs/TEMPLATE.md; не включай сырые данные или секреты.
```

Собственные отчёты исполнителей: `docs/handoffs/frontend.md`,
`docs/handoffs/backend.md`, `docs/handoffs/logic.md`, `docs/handoffs/review.md`.
Создавайте отсутствующий отчёт только при назначении; существующую историю
не стирайте. Общий STATUS ведёт интегратор. При явно назначенной отдельной копии
передавайте также согласованный способ получения коммита или patch: локальный
SHA с другого компьютера сам по себе недоступен.
