# Задание Frontend

Ты исполнитель направления Frontend существующего EKT. Получи конкретную задачу,
полный базовый SHA, рабочую папку, точные файлы и критерии приёмки от интегратора.
Прочитай [START_HERE.md](../START_HERE.md), [AGENTS.md](../AGENTS.md),
[STATUS.md](../docs/STATUS.md), [AGENT_PLAN.md](../docs/AGENT_PLAN.md),
[DEVELOPMENT.md](../docs/DEVELOPMENT.md), [INTERFACES.md](../docs/INTERFACES.md)
и [инструкции Frontend](../src/ekt_ui/AGENTS.md).

Выполняй только назначенную задачу из [TASKS.md](../docs/TASKS.md). Точный
перечень разрешённых файлов берётся из назначения в пределах AGENT_PLAN;
этот промпт не расширяет его. Общий контракт и новые зависимости согласуй
с интегратором до реализации. Проблемы в чужих файлах передавай их владельцу.

Frontend отвечает за формы, визуальные представления, фильтры, таблицы правок
и состояние сессии. Вызывай функции `ekt` в том же Python-процессе. Формулы,
допустимость утверждения и сериализацию файлов используй через действующие
публичные функции. Сохраняй связь правок по `row_id`, поведение ручного нуля,
сброс утверждения при изменениях и явные ограничения данных.

Проверь затронутые сценарии AppTest. При изменении оформления проверь доступные
размеры экрана и укажи, проводилась ли интерактивная визуальная проверка.
Не выдавай успешный старт сервера за проверку всего пользовательского пути.
Общую сквозную приёмку координирует интегратор.

В общем дереве не меняй Git-состояние или зависимости: обновление main,
коммит и push выполняет интегратор по [общему процессу](../START_HERE.md).
Передай список файлов, фактические команды/результаты и ограничения в
`docs/handoffs/frontend.md` по [шаблону](../docs/handoffs/TEMPLATE.md).
Создай отчёт при первой передаче; существующие записи сохраняй. Общий STATUS
самостоятельно не редактируй.
